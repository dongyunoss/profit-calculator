# 자산운용 수익률 관리 (Profit Calculator)

자산 운용자가 여러 계좌의 수익률을 펀드 기준가(NAV) 방식으로 관리하는 웹사이트입니다.
빌드 도구·프레임워크 없이 순수 HTML/CSS/JS로 되어 있습니다.

데이터는 기본적으로 **브라우저(localStorage)** 에 저장되며, Cloudflare에 배포하면
**여러 컴퓨터에서 같은 데이터를 함께 쓰는 서버 동기화**가 켜집니다(→ [서버 동기화](#서버-동기화)).
서버를 붙이지 않아도 기능은 그대로 동작합니다.

## 실행 방법

`index.html`을 브라우저로 열면 바로 사용할 수 있습니다(로컬 전용 모드).

로컬 서버로 띄우려면:

```bash
npm start          # node server.js → http://localhost:3000
```

또는 Node 없이:

```bash
python3 -m http.server 8000
# → http://localhost:8000
```

## UI

**다크/라이트 두 테마** — 색은 전부 `:root` 토큰으로만 쓰고, 라이트 테마는
`[data-theme="light"]`에서 같은 토큰을 덮어쓰는 것으로 끝납니다(컴포넌트 규칙은 그대로).
좌측 하단 **해/달 버튼**으로 전환하며, 선택은 저장되고 저장값이 없으면 OS 설정을 따릅니다.
기본 다크 배경 `#14161a`, 액센트 청록 `#4fb3c9`, 손익 색은 한국 관례(이익 적색 / 손실 청색)입니다.

좌측 **계좌 레일(268px)** 에서 계좌를 한 번에 선택하고, 모든 수치는 등폭 서체 +
`tabular-nums` 로 자릿수가 맞습니다. 화면 폭에 맞춰 좌측 레일·KPI 카드·입력 폼이 접히므로
좁은 창에서도 페이지가 옆으로 밀리지 않습니다(열이 많은 표만 표 내부에서 가로 스크롤).

**모바일(≤640px)** 은 국내 증권사 MTS 관례를 참고해 조회 위주로 별도 조정됩니다 — 데스크톱
레이아웃·스타일은 전혀 바뀌지 않고, 모바일 전용 미디어쿼리 안에서만 적용됩니다.
- **억/만 단위 축약** — "55,967,232,129원"처럼 자릿수가 많은 금액을 "559억 6,723만원"으로.
  KPI 카드·계좌 레일·계좌 목록·상세 지표·원금 입출금 요약처럼 "한눈에 보는" 자리에만 적용되고,
  원금 원장·거래 이력처럼 대사(reconciliation)가 필요한 표는 항상 전체 자릿수를 유지합니다.
- **손익 화살표(▲/▼)** — 색만으로는 구분하기 어려운 흑백 캡처·색약 사용자를 위해 방향 화살표를
  같이 표시합니다.
- **계좌 레일**이 세로 목록 대신 가로로 스와이프하는 칩으로 바뀝니다.
- **계좌 목록**은 표 대신 보유종목 리스트 같은 2~3줄 카드형으로 — 계좌명 → 평가금액·평가손익 →
  원금대비 수익률(크게 강조) 순. 터치로는 동작하지 않는 순서 변경 열은 숨깁니다.
- **차트**는 좁은 화면에서 여백·눈금·글자 크기를 줄여 더 넓은 플롯 영역을 확보합니다.
- 창 크기를 조절하거나 화면을 회전해 모바일↔데스크톱 기준을 넘나들면 표기가 즉시 다시 그려집니다.

폰트 2종만 CDN에서 불러오며(본문 Noto Sans KR / 숫자 JetBrains Mono), 오프라인에서는
시스템 서체로 자연스럽게 대체됩니다 — 그 외 외부 의존성은 없습니다.

## 주요 기능

| 기능 | 설명 |
|------|------|
| 계좌별 기준가·좌수 | 기준가는 1,000좌당 가격, 개설 시 1,000.00 시작. 일일 평가금액 입력 시 `기준가 = 평가금액 × 1000 ÷ 좌수` 로 갱신 |
| 계좌별 수익률 | 기준가 수익률·원금대비 수익률(**계약 기준** — 보수 수취·재계약 후 기산), 원금흐름대비 수익률·누적 성과 수익률(보수 수취·재계약 무관, 개설 이후). 원금대비·원금흐름대비 모두 **총수익(Total Return) 기준** — 배당·보수로 나간 금액을 되살려 계산 |
| 원금의 두 기준 | **계약원금(계약 기준)** — 보수 수취·재계약 시 평가금액으로 승계되는 현재 계약의 원금. **개별 계좌를 눌러 들어갔을 때 쓰는 기준**입니다. **원금 흐름(흐름 기준)** — 입금 − 출금만 반영하는 원금. **전체 성과 측정에 쓰는 기준**이며 보수·재계약으로 변하지 않습니다 |
| 계좌 상세 원장 | 계좌를 선택하면 **원금 원장**(원금 → 추가입금·출금)과 **일별 평가·수익률**(일자·평가금액·원금대비 수익률·기준가 수익률·기준가)을 2단으로 표시. 원장의 각 행을 더하면 '현재 원금'이 그대로 나옵니다. 좌수 증감·일간 수익률까지 보려면 아래 **상세 거래·평가 이력**을 펼칩니다 |
| 입출금 | 현재 기준가로 좌수를 발행/환매 → 입출금이 수익률을 왜곡하지 않음 |
| 전액 출금(해지) | 현재 평가금액 전액을 출금하고 계좌를 해지 상태로 전환. 원금 흐름에서는 **남은 원금**(보수 차감 전 기준의 계약원금)을 차감하므로, **같은 정리를 일반 출금으로 기입해도 전체 성과가 동일**하게 나옵니다. 해지 시점까지의 성과는 종합 성과 수익률에 보존됨 |
| 성과보수 수취 | **펀드 배당(분배금) 지급과 동일한 회계** — 원금에서 차감되지 않고, 나간 금액은 수익률 계산에서 되살아나 수익률도 깎이지 않음. 수취 시점에는 만기 재계약과 같이 기준가 1,000 / 기준가·원금대비 수익률 0%로 초기화하고, 보수 차감 후 평가금액을 **새 계약의 원금으로 승계** |
| 배당·이익지급 | 이자·쿠폰·배당·상환수익의 인출. 두 기준의 원금을 모두 줄이지 않으며, 계약 기준·흐름 기준 수익률 모두 지급액을 되살려 계산하므로 **지급할 때마다 수익률이 깎이지 않음** |
| 종합 성과 수익률 | 계좌별 일간 기준가 수익률을 직전 평가금액 가중으로 체인링크한 컴포지트 지수 (1,000 시작) |
| 원금대비 단순 수익률 | (총 평가금액 + 누적 성과보수 + 누적 이익지급 − 총 원금) ÷ 총 원금 — 이미 지급·수취되어 계좌 밖으로 나간 성과를 되살려, 보수 수취·재계약으로 전체 수익률이 깎여 보이지 않게 함 |
| 수익률 추이 차트 | 종합 성과 지수 / 계좌별 누적 수익률을 인라인 SVG 라인 차트로 시각화. 계좌별 보기에서 **범례의 계좌명을 클릭하면 해당 계좌만** 표시(다시 클릭 시 전체) |
| 벤치마크(코스피) | 계좌 목록 상단의 **코스피 지수** 입력란에 일자·지수를 입력하면 차트에 **점선**으로 함께 표시되고, 가장 이른 계좌 설정일 대비 변동률이 바로 계산됩니다. 차트 시작 시점을 0%로 맞춰 비교하며, 휴장일·평가일이 어긋나면 직전 지수값을 씁니다. 엑셀 '종합지수' 시트에도 열로 포함 |
| 계좌 이름 변경 | 계좌를 선택하면 상세 창 제목 옆 연필(✎) 아이콘으로 이름 변경 |
| 계좌 순서 변경 | 계좌 목록의 행을 **끌어서(드래그) 놓아** 순서 변경. 순서는 저장되어 요약·차트·엑셀에도 동일하게 반영 |
| 엑셀 다운로드 | **종합** + 종합요약 + 종합지수 시계열 + 원금원장 + 계좌별 거래·평가 이력을 .xlsx로 저장 (외부 라이브러리 없이 자체 생성) |
| 종합 시트 | 전 계좌를 한 장에 가로로 나란히. **윗단** 계좌별 원금 원장(원금 → 추가입금 → 원금합, 최종 원금합 노랑 강조), **아랫단** 일자별 평가금액·원금대비 수익률(입출금이 있던 날 분홍 강조) |
| 원금 입출금 내역 | '원금 입출금 내역' 버튼 → 전 계좌 집계·통합 내역과 **계좌별 원금 원장**을 계좌별 열로 나란히 표시. 엑셀에도 '원금원장' 시트로 포함 |
| PDF 리포트 | 'PDF 리포트' 버튼 → 포함할 계좌를 고르면 **계좌당 A4 한 장**으로 인쇄용 레이아웃을 생성 (브라우저 인쇄 기능 사용, 외부 라이브러리 없음) |
| 백업/복원 | 전체 데이터를 JSON으로 내려받고 복원 |
| 서버 동기화 | Cloudflare 배포 시 여러 컴퓨터에서 같은 데이터를 사용. **⟳ 동기화** 버튼으로 즉시 확인하고, 평소에는 1분 주기로 조용히 감지 (→ [서버 동기화](#서버-동기화)) |
| 화면 모드 | 좌측 하단 해/달 버튼으로 다크·라이트 전환, 선택은 저장됨 |

> **누적 성과보수**는 화면에는 표시하지 않고 **엑셀 다운로드**(종합요약·계좌별 시트)에만
> 포함됩니다. 수익률 계산에는 그대로 반영됩니다(총수익 기준).

## 사용 흐름

1. **계좌 추가** — 계좌명, 개설일, 초기 원금을 입력합니다.
2. **일일 평가금액 입력** — 영업일 장 마감 후 각 계좌의 평가금액을 입력합니다.
   같은 날짜에 다시 입력하면 덮어씁니다.
3. **입출금** — 원금 입출금이 있으면 입력합니다. 현재 기준가로 좌수가 증감되어
   성과 측정이 왜곡되지 않습니다.
4. **성과보수 수취** — 보수액을 입력하면 평가금액에서 차감된 뒤, **만기 재계약과 같은 방식으로**
   기준가·수익률이 초기화됩니다 (하이워터마크 리셋). 보수 차감 후 평가금액이 새 계약의
   원금으로 승계되어 원금대비 수익률도 0%가 됩니다. 전체 성과는 원금 흐름 기준이라 총원금과
   수익률이 그대로 유지됩니다.
5. **벤치마크 입력**(선택) — 계좌 목록 상단의 **코스피 지수** 입력란에 일자와 지수를 입력하면
   차트에 비교선이 추가됩니다.
6. **내보내기** — **엑셀 다운로드**로 전체 현황을 .xlsx로, **PDF 리포트**로 고른 계좌를
   계좌당 한 장씩 내려받습니다.

## 계산 규칙

기호까지 포함한 전체 계산식은 [`docs/계산식.md`](docs/계산식.md)에 정리해 두었습니다.

- 같은 날짜의 입금/출금/평가는 **입력한 순서대로** 처리됩니다 (실제 발생 순서와 일치).
  - 입금을 먼저 기입하고 평가금액(입금 포함 잔고)을 나중에 입력 → 입금은 직전 기준가로 반영
  - 평가금액을 먼저 입력하고 입금을 나중에 기입(장 마감 후 입금 등) → 입금은 그날 갱신된
    기준가로 반영되어 **수익률이 희석되지 않습니다**
- **성과보수·이익 지급은 입력 순서와 무관하게 당일 평가 반영 후**에 처리됩니다.
  보수를 먼저 수취하고 평가금액을 나중에 입력해도 기준가 수익률은 정확히 0%로 초기화되고,
  종합 성과 수익률은 오염되지 않습니다. 당일 평가금액은 **보수 차감 전** 금액으로 입력하세요.
- **전액 출금(해지)은 그날의 가장 마지막**(보수 처리 후)에 처리됩니다. 같은 날 "평가 →
  보수 수취 → 전액 출금"을 함께 입력해도 순서가 보장됩니다. 해지된 계좌는 이후 종합 성과
  수익률 가중치에서 제외되며, 해지 시점까지의 성과는 지수에 그대로 남습니다. 해지 후
  다시 입금하면 기준가 1,000에서 새로 시작합니다.
- 입금: `추가 좌수 = 입금액 × 1000 ÷ 기준가`, 출금: `차감 좌수 = 출금액 × 1000 ÷ 기준가`
- 성과보수·배당은 성과가 아닌 자금 유출(flow)로 처리되어 누적 성과 수익률을 훼손하지 않습니다.
- **총수익(Total Return) 기준.** 펀드가 배당을 지급하면 순자산은 줄지만 원금은 줄지 않습니다.
  이때 수익률을 "지급 후 잔액 ÷ 원금"으로 재면 지급한 만큼 수익률이 사라져 버리므로,
  계좌 밖으로 나간 금액(배당·이자·성과보수)을 수익률 분자에 되살려 계산합니다.
  - 기준가 수익률 — 지급액만큼 좌수를 상환하므로 기준가 자체가 변하지 않아 왜곡 없음(시간가중)
  - 원금대비 수익률(계약 기준) — 계약 시작 이후 나간 금액을 되살림
  - 원금흐름대비·전체 성과 수익률 — 개설 이후 나간 금액 전부를 되살림
  - 기준가 수익률은 지급액을 재투자한 것으로 보므로, 실제로 인출한 경우 원금대비 수익률과
    재투자 복리분만큼 차이가 날 수 있습니다(예: 1억 → 분기 배당 300만·400만 지급 시
    기준가 7.12% vs 원금대비 7.00%).
- **전액 출금(해지)과 일반 출금은 같은 결과를 냅니다.** 해지는 원금 흐름에서 "남은 원금"
  (보수 차감 전 기준의 계약원금)을 차감하는데, 이는 계좌를 정리할 때 손으로 기입하는
  출금액과 같은 기준입니다. 어느 쪽으로 기입해도 총원금·총성과·단순 수익률이 동일합니다.
  이익까지 인출한 계좌는 원금이 음수가 되며, 그만큼이 실현이익으로 잡힙니다.
  - 해지 시 **원금 차감액과 실제 인출 현금은 다를 수 있습니다.** 원금 원장의 해지 행은
    원금 차감액을 금액으로 표시하고, 그 아래 `인출 ○○ + 손실정리 ○○`(이익 상태면
    `− 이익정리`)로 근거를 함께 보여줍니다.
    (예: 남은 원금 183.1억 = 인출 161.5억 + 손실정리 21.6억)
- **성과보수 수취는 만기 재계약과 동일한 회계로 처리됩니다.** 보수 차감 후 평가금액이 새 계약의
  원금(계약원금)으로 승계되므로 개별 계좌는 기준가·원금대비 수익률이 모두 0%로 초기화되고,
  전체 성과는 원금 흐름 기준이므로 총원금과 수익률이 그대로 유지됩니다.
  (예: 원금 1억 → 평가 1.1억 → 보수 200만 수취 ⇒ 개별 계좌는 계약원금 1.08억·원금대비 0%,
  전체 성과는 총원금 1억·단순 수익률 10% 유지)
- 종합(컴포지트) 일간 수익률: 해당 일자에 평가가 없는 계좌는 수익률 0으로,
  직전 평가금액만큼 가중치에 포함됩니다.

### 성과보수 수취 = 만기 재계약 회계

성과보수 수취는 실물 자산(예금·채권·ELS·폐쇄형 펀드)의 **만기 재계약 처리 관행**을 그대로 따릅니다.
만기에 원리금을 새 계약 원금으로 재예치하듯, 보수 차감 후 평가금액을 새 계약의 원금으로 승계합니다.

| 구분 | 만기 재계약 | 성과보수 수취 |
|------|------------|--------------|
| 새 계약 원금 | 만기 원리금 | 보수 차감 후 평가금액 |
| 기준가 | 1,000으로 초기화 | 1,000으로 초기화 |
| 계약 기준 수익률 | 0% | 0% |
| 누적 성과 · 전체 실적 | 그대로 이어짐 | 그대로 이어짐 |

- **개별 계좌는 완전히 초기화됩니다.** 기준가 수익률과 원금대비 수익률이 모두 0%가 되고,
  원금(계약원금)은 보수 차감 후 평가금액으로 승계됩니다.
- **전체 성과는 그대로 유지됩니다.** 총원금은 원금 흐름 기준이라 보수 수취로 변하지 않고,
  수취한 보수는 원금대비 단순 수익률에 다시 가산되어 전체 수익률이 깎이지 않습니다.
- **초기화 이후 계약 안에서 배당을 지급해도 그 계약의 원금대비 수익률은 깎이지 않습니다.**
  (예: 계약원금 1.08억 → 평가 1.188억 → 배당 300만 지급 ⇒ 잔액 1.158억, 원금대비 여전히 10%)
- 누적 성과 수익률과 종합 성과 지수는 보수 수취와 무관하게 연속됩니다.

> 엔진은 만기(maturity)·이익지급(payout)·재계약(rollover) 이벤트도 계속 지원합니다.
> 화면 입력 폼은 없지만, JSON 복원으로 들어온 해당 내역은 정상적으로 계산됩니다.

## 서버 동기화

Cloudflare에 배포하면 여러 컴퓨터·휴대폰에서 같은 데이터를 함께 쓸 수 있습니다.
**정적 자산이 딸린 Worker**(`wrangler deploy`) 형태로, 데이터는 **D1**(SQLite) 한 행에
JSON으로 저장됩니다. 설정 절차는 [`docs/배포.md`](docs/배포.md)에 있습니다.

- **localStorage는 계속 캐시로 씁니다.** 서버가 원본이고 로컬은 캐시라, 네트워크가 끊겨도
  화면은 그대로 뜨고 입력한 내용이 사라지지 않습니다.
- **API가 없으면**(로컬 파일로 열기·서버 미배포) 조용히 로컬 전용으로 동작합니다.
- **접속은 링크의 공유 코드로만** 구분합니다. 로그인 화면이 없고, 최초 접속 시 URL의
  `?key=...` 값을 저장한 뒤 주소창에서 지웁니다. 이후 매 요청에 `X-Site-Key` 헤더로 보냅니다.
  서버에 `SITE_KEY`가 없거나 일치하지 않으면 거부합니다(fail-closed).
- **⟳ 동기화 버튼**으로 서버 최신본을 즉시 확인합니다. 평소에는 **1분 주기**로 조용히 확인하고
  (탭이 숨겨지면 멈춤), 편집 중일 때는 화면을 덮어쓰지 않습니다.
- **충돌** — 내가 읽은 뒤 다른 곳에서 먼저 저장했으면 묻지 않고 서버 최신본으로 맞춥니다.
  이때 이 컴퓨터에서 입력하던 내용은 따로 보관하고, 토스트의 **'보관본 내려받기'** 로
  꺼낼 수 있습니다.
- **저장 이력**을 최근 30개까지 D1에 남깁니다. "실수로 덮어썼다"를 되돌릴 수 있는 안전망으로,
  꺼내는 방법은 [`docs/배포.md`](docs/배포.md)의 '운영' 절에 있습니다.

> `SITE_KEY`는 비밀값이라 저장소에 두지 않고 Cloudflare 대시보드에 Secret으로 등록합니다.
> 짧은 코드는 전수 시도가 쉬우니 `openssl rand -hex 24` 같은 긴 값을 쓰세요.

## 프로젝트 구조

```
index.html              # 화면
css/styles.css          # 스타일 (다크/라이트 토큰)
js/engine.js            # 기준가/좌수 계산 엔진 (순수 함수, 테스트 가능)
js/app.js               # 화면 렌더링·이벤트 처리·저장
js/sync.js              # 서버(/api/state) 동기화 계층 — 디바운스·재시도·충돌 감지
js/xlsx-writer.js       # 의존성 없는 경량 .xlsx 생성기
js/chart.js             # 의존성 없는 인라인 SVG 라인 차트 (수익률 추이)
tests/engine.test.js    # 계산 검증 테스트

server.js               # 로컬 개발용 정적 파일 서버
src/worker.js           # Cloudflare Worker 진입점 (/api/state + 정적 자산)
functions/api/state.js  # 상태 저장·조회 API (SITE_KEY 검증, 낙관적 동시성)
schema.sql              # D1 테이블 정의
wrangler.toml           # Cloudflare 배포 설정

docs/배포.md            # Cloudflare 배포 절차
docs/계산식.md          # 금액·수익률 계산식 전체 정리
docs/원금-마이너스-개선안.md   # 검토용 문서 (코드에 미적용)
```

사이트가 쓰는 런타임 의존성은 **없습니다**(폰트 CDN 제외). `package.json`의 `xlsx`와
저장소 루트의 `build-kim-account.js`·`create-sample-xlsx.js`·샘플 JSON/xlsx는 데이터를
한 번씩 만들어 볼 때 쓴 보조 도구이며, 화면 동작과는 무관합니다.
