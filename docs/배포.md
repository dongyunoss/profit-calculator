# Cloudflare 배포 — 다른 컴퓨터에서 같은 데이터 보기

여러 대에서 같은 데이터를 쓰되, **허용한 사람만** 들어오게 하는 구성이다.
전부 Cloudflare 무료 플랜 범위 안이고, 쓰지 않아도 멈추지 않는다.

| 구성 | 역할 |
|---|---|
| **Pages** | 사이트 호스팅 (상업적 사용 허용, 대역폭 무제한) |
| **Access** | 로그인 게이트 — 지정한 이메일만 통과 (50명까지 무료) |
| **D1** | 계좌 데이터 저장 (5GB 무료) |
| **Pages Functions** | `/api/state` 읽기·쓰기 |

> 데이터는 현재 약 150KB다. 무료 한도에 한참 못 미친다.

---

## 준비

```bash
npm install -g wrangler
wrangler login
```

---

## 1. D1 데이터베이스 만들기

```bash
wrangler d1 create profit-calculator
```

출력에 나오는 `database_id`를 **`wrangler.toml`의 `database_id`**에 붙여 넣는다.

이어서 테이블을 만든다.

```bash
wrangler d1 execute profit-calculator --remote --file=./schema.sql
```

---

## 2. Pages 프로젝트 만들기

Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
→ 이 저장소를 선택.

빌드 설정은 비워 둔다(빌드 도구가 없는 정적 사이트다).

| 항목 | 값 |
|---|---|
| Framework preset | None |
| Build command | *(비움)* |
| Build output directory | `/` |

배포가 끝나면 `https://<프로젝트>.pages.dev` 주소가 생긴다.

---

## 3. D1 연결

Pages 프로젝트 → **Settings** → **Bindings** → **Add** → **D1 database**

| 항목 | 값 |
|---|---|
| Variable name | `DB` |
| D1 database | `profit-calculator` |

---

## 4. Access로 막기 — **데이터를 올리기 전에 반드시 먼저**

Cloudflare 대시보드 → **Zero Trust** → **Access** → **Applications** → **Add an application**
→ **Self-hosted**

| 항목 | 값 |
|---|---|
| Application name | 아무 이름 |
| Session Duration | 24시간 정도 |
| Public hostname | `<프로젝트>.pages.dev` (서브도메인 칸은 **비움**) |

정책(Policy)을 하나 만든다.

| 항목 | 값 |
|---|---|
| Policy name | 예: 허용 인원 |
| Action | Allow |
| Include | **Emails** → 들어올 사람의 이메일을 나열 |

만들고 나면 **Overview 탭의 Application Audience (AUD) Tag**를 복사해 둔다. 다음 단계에서 쓴다.

> 팀 도메인은 Zero Trust → Settings → Custom Pages 부근에 `<팀이름>.cloudflareaccess.com` 형태로 표시된다.

---

## 5. 환경 변수 등록

Pages 프로젝트 → **Settings** → **Variables and Secrets** → Production에 두 개를 넣는다.

| 이름 | 값 |
|---|---|
| `ACCESS_TEAM_DOMAIN` | `<팀이름>.cloudflareaccess.com` |
| `ACCESS_AUD` | 4단계에서 복사한 AUD 태그 |

넣은 뒤 **재배포**한다(Deployments → 최신 배포 → Retry deployment).

> 이 두 값이 없으면 API는 데이터를 내주지 않고 500을 돌려준다. 설정이 빠진 채로
> 데이터가 열리는 일이 없게 일부러 그렇게 막아 두었다.

---

## 6. 첫 접속 — 데이터 옮기기

지금까지 쓰던 **그 컴퓨터, 그 브라우저**로 `https://<프로젝트>.pages.dev` 를 연다.

1. Access 로그인 화면이 뜬다 → 허용한 이메일로 로그인
2. 앱이 열리면서 이 브라우저에 있던 계좌 데이터를 서버로 자동으로 올린다
3. 헤더에 **"저장됨"** 배지가 뜨면 완료

> 순서가 중요하다. 다른 컴퓨터에서 먼저 열면 서버가 빈 상태로 시작해 버린다.
> 만약 그렇게 됐다면, 원래 컴퓨터에서 **백업 → 복원**으로 데이터를 올리면 된다.

---

## 7. 다른 컴퓨터에서 확인

같은 주소를 열고 허용된 이메일로 로그인하면 같은 데이터가 보인다.

---

## 화면의 동기화 배지

헤더 오른쪽에 상태가 표시된다.

| 표시 | 뜻 |
|---|---|
| *(없음)* | 서버 없이 이 브라우저에만 저장 중 (로컬 실행) |
| 동기화 중… | 서버에서 불러오는 중 |
| 저장 중… | 서버로 올리는 중 |
| **저장됨** | 정상. 마우스를 올리면 마지막 저장자·시각이 보인다 |
| **연결 안 됨** | 서버에 못 올렸다. 입력은 이 컴퓨터에 남아 있고, 연결되면 자동으로 올라간다 |
| **다른 곳에서 먼저 저장됨** | 충돌. 어느 쪽을 살릴지 묻는 창이 뜬다 |

---

## 동시에 편집하면

두 사람이 같은 시간에 고치면, 나중에 저장하는 쪽이 **충돌 안내**를 받는다.
조용히 덮어쓰지 않는다.

- **서버 내용 가져오기** — 내 입력을 버리고 서버 것을 받는다
- **취소** — 내 화면은 그대로 두지만 서버에는 저장되지 않은 상태다.
  이때는 백업(JSON)을 받아 두고 새로고침한 뒤 다시 입력하는 편이 안전하다

---

## 운영

**백업** — 서버가 생겼어도 정기 백업은 계속 받아 두는 게 좋다.
헤더의 **백업** 버튼으로 JSON을 내려받으면 된다.

**되돌리기** — 최근 30번의 저장 스냅샷이 남는다.

```bash
# 최근 저장 이력 보기
wrangler d1 execute profit-calculator --remote \
  --command "SELECT version, updated_at, updated_by FROM app_state_history ORDER BY version DESC LIMIT 30;"

# 특정 버전 내용 꺼내기 (파일로 저장한 뒤 앱의 '복원'으로 올리면 된다)
wrangler d1 execute profit-calculator --remote --json \
  --command "SELECT data FROM app_state_history WHERE version = 42;"
```

**사람 추가·제외** — Zero Trust → Access → Applications → 정책의 이메일 목록을 고친다.
앱은 손대지 않아도 된다.

---

## 안 될 때

| 증상 | 원인 |
|---|---|
| `ACCESS_TEAM_DOMAIN / ACCESS_AUD 가 설정되지 않았습니다` | 5단계 환경 변수 누락. 등록 후 재배포 |
| `Access 인증 정보가 없습니다` | Access 애플리케이션이 이 주소를 안 덮고 있다. 4단계의 hostname 확인 |
| `이 애플리케이션용 토큰이 아닙니다` | `ACCESS_AUD` 값이 애플리케이션의 AUD와 다르다 |
| `D1 바인딩(DB)이 설정되지 않았습니다` | 3단계 바인딩 누락 |
| 배지가 안 보임 | Functions가 배포되지 않았다. `functions/` 폴더가 저장소에 있는지 확인 |

---

## 로컬에서 그대로 쓰기

`/api/state`가 없으면 앱은 **예전처럼 이 브라우저에만 저장**한다. 배지도 숨는다.
개발용 `node server.js`나 파일로 직접 열 때 그대로 동작한다.
