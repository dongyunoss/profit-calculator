# Cloudflare 배포 — 다른 컴퓨터에서 같은 데이터 보기

여러 대에서 같은 데이터를 쓰되, **링크에 코드가 있는 사람만** 들어오게 하는 구성이다.
로그인 화면·이메일 인증 없이, 주소 끝에 붙는 코드 하나로 막는다.
전부 Cloudflare 무료 플랜 범위 안이고, 쓰지 않아도 멈추지 않는다.

| 구성 | 역할 |
|---|---|
| **Workers (정적 자산)** | 사이트 호스팅 (상업적 사용 허용, 대역폭 무제한) |
| **D1** | 계좌 데이터 저장 (5GB 무료) |
| **Worker (`src/worker.js`)** | `/api/state` 읽기·쓰기 — 나머지 경로는 정적 자산으로 넘김 |
| **접속 코드 (`SITE_KEY`)** | 로그인 대신 링크에 붙이는 비밀 코드 하나로 막는다 |

> 데이터는 현재 약 150KB다. 무료 한도에 한참 못 미친다.

> **참고 — 왜 로그인이 아니라 코드 방식인가.** Cloudflare Zero Trust Access(이메일 로그인)도
> 검토했지만, 설정 단계가 많고(애플리케이션 생성·정책·AUD 태그·환경변수) 매번 이메일 인증을
> 거쳐야 해서 더 간단한 쪽을 택했다. **다만 코드가 새어 나가면 그 코드를 아는 사람은 누구나
> 데이터를 볼 수 있다.** 실제 고객 이름·자산 금액이 들어가는 데이터이므로, 링크를 messenger 등에
> 그대로 붙여넣지 말고 필요한 사람에게만 개별로 전달하는 걸 권한다. 여러 사람의 접근을
> 개별적으로 켜고 끄고 싶어지면 이메일 로그인(Access) 방식으로 바꿀 수 있다.

> Git 연동 시 Cloudflare 대시보드에서 "Pages"를 선택해도, 실제 빌드·배포는
> classic Pages가 아니라 **정적 자산이 딸린 Worker**(`wrangler deploy`) 방식으로 처리된다.
> 그래서 `functions/` 폴더의 파일 기반 라우팅(Pages Functions)은 자동으로 동작하지 않고,
> `src/worker.js`가 `/api/state`만 직접 연결한 뒤 나머지는 `env.ASSETS`로 넘긴다.
> `wrangler.toml`의 `[assets]`가 이 정적 자산을 정의하고, `.assetsignore`가 `docs/`·`schema.sql`·
> `src/`·`functions/` 등 앱 화면과 무관한 파일이 웹 경로로 함께 올라가지 않게 막는다.

---

## 준비

```bash
npm install -g wrangler
wrangler login
```

---

## 1. D1 데이터베이스 만들기

```bash
wrangler d1 create profit-calculator
```

출력에 나오는 `database_id`를 **`wrangler.toml`의 `database_id`**에 붙여 넣는다.

이어서 테이블을 만든다.

```bash
wrangler d1 execute profit-calculator --remote --file=./schema.sql
```

(CLI 대신 대시보드로 하고 싶으면: **Workers & Pages → D1 SQL Database → Create Database** →
만든 뒤 **Console** 탭에 `schema.sql` 내용을 붙여넣어 실행해도 된다. 이 경우 Database ID는
데이터베이스 상세 화면에서 바로 보인다.)

---

## 2. Pages 프로젝트 만들기

Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
→ 이 저장소를 선택.

빌드 설정은 비워 둔다(빌드 도구가 없는 정적 사이트다).

| 항목 | 값 |
|---|---|
| Framework preset | None |
| Build command | *(비움)* |
| Build output directory | `/` |

배포가 끝나면 `https://<프로젝트>.pages.dev` 주소가 생긴다.

> D1 바인딩은 `wrangler.toml`의 `[[d1_databases]]`에 이미 선언돼 있어서, 대시보드에서
> 따로 바인딩을 연결하지 않아도 배포 시 자동으로 잡힌다.

---

## 3. 접속 코드(SITE_KEY) 만들고 등록하기 — **데이터를 올리기 전에 반드시 먼저**

임의의 긴 문자열을 하나 만든다.

```bash
openssl rand -hex 24
```

Pages 프로젝트 → **Settings** → **Variables and Secrets** → **Add** →

| 항목 | 값 |
|---|---|
| Variable name | `SITE_KEY` |
| Value | 위에서 만든 문자열 |
| Type | **Secret** (평문 Variable이 아니라 Secret으로 — 등록 후엔 값이 다시 안 보인다) |

넣은 뒤 **재배포**한다(Deployments → 최신 배포 → Retry deployment).

> 이 값이 없으면 API는 데이터를 내주지 않고 500을 돌려준다. 설정이 빠진 채로
> 데이터가 열리는 일이 없게 일부러 그렇게 막아 두었다.

---

## 4. 첫 접속 — 데이터 옮기기

지금까지 쓰던 **그 컴퓨터, 그 브라우저**로 아래 주소를 연다 (`<코드>`는 3단계에서 만든 값).

```
https://<프로젝트>.pages.dev/?key=<코드>
```

1. 접속하면 코드가 자동으로 저장되고, 주소창에서는 곧바로 지워진다(기록에 코드가 남지 않도록)
2. 앱이 열리면서 이 브라우저에 있던 계좌 데이터를 서버로 자동으로 올린다
3. 헤더에 **"저장됨"** 배지가 뜨면 완료

> 순서가 중요하다. 다른 컴퓨터에서 먼저 열면 서버가 빈 상태로 시작해 버린다.
> 만약 그렇게 됐다면, 원래 컴퓨터에서 **백업 → 복원**으로 데이터를 올리면 된다.

---

## 5. 다른 컴퓨터에서 확인

**같은 `?key=<코드>` 링크**를 다른 컴퓨터에서 열면 같은 데이터가 보인다. 코드는 그 브라우저에
저장되므로, 한 번 연 뒤에는 `https://<프로젝트>.pages.dev` (코드 없이)만 열어도 계속 된다.

> 코드를 전달할 사람에게는 `?key=` 가 붙은 전체 링크를 보내면 된다. 화면·주소창에는
> 코드가 남지 않지만, 메신저 대화방 등에는 코드가 그대로 텍스트로 남으니 전달 경로에 유의한다.

---

## 화면의 동기화 배지

헤더 오른쪽에 상태가 표시된다.

| 표시 | 뜻 |
|---|---|
| *(없음)* | 서버 없이 이 브라우저에만 저장 중 (로컬 실행) |
| 동기화 중… | 서버에서 불러오는 중 |
| 저장 중… | 서버로 올리는 중 |
| **저장됨** | 정상. 마우스를 올리면 마지막 저장 시각이 보인다 |
| **연결 안 됨** | 서버에 못 올렸다(끊김·코드 오류 등). 입력은 이 컴퓨터에 남아 있다 |

**연결 안 됨** 상태에서 배지를 클릭하면 접속 코드를 다시 입력할 수 있다. 코드가 틀렸거나
브라우저 데이터를 지워서 코드가 사라졌을 때 이 방법으로 복구한다(링크를 다시 받지 않아도 됨).

---

## 동시에 편집하면

**내가 화면을 연 뒤 다른 곳에서 먼저 저장했다면, 묻지 않고 그 최신 내용으로 맞춘다.**
항상 최신이 우선이므로 오래된 내용이 남는 일이 없다.

이때 이 컴퓨터에서 입력하던 내용은 그대로 사라지지 않는다.

- 화면 아래에 안내가 뜨고, **보관본 내려받기** 버튼이 함께 나온다
- 그 버튼을 누르면 최신화 직전의 내 내용이 JSON으로 내려받아진다
- 필요한 부분은 다시 입력하거나, 그 파일을 **복원**으로 통째로 올리면 된다

> 보관본은 이 브라우저에 한 벌만 남는다(다음 최신화 때 덮어쓴다).
> 되살릴 내용이 있으면 그 자리에서 내려받아 두는 편이 안전하다.

**서버가 그대로였다면** 최신화하지 않는다. 연결이 끊긴 동안 입력한 내용은
다음 접속 때 서버로 올라간다 — 아무도 건드리지 않은 변경을 버리지는 않는다.

---

## 운영

**백업** — 서버가 생겼어도 정기 백업은 계속 받아 두는 게 좋다.
헤더의 **백업** 버튼으로 JSON을 내려받으면 된다.

**되돌리기** — 최근 30번의 저장 스냅샷이 남는다.

```bash
# 최근 저장 이력 보기
wrangler d1 execute profit-calculator --remote \
  --command "SELECT version, updated_at FROM app_state_history ORDER BY version DESC LIMIT 30;"

# 특정 버전 내용 꺼내기 (파일로 저장한 뒤 앱의 '복원'으로 올리면 된다)
wrangler d1 execute profit-calculator --remote --json \
  --command "SELECT data FROM app_state_history WHERE version = 42;"
```

**코드가 새어 나갔다고 의심되면** — `SITE_KEY`를 새 값으로 바꾸고 재배포한다(3단계와 동일).
그 순간부터 옛 코드가 붙은 링크는 전부 무효가 된다. 계속 쓸 사람들에게는 새 링크를
`?key=<새 코드>` 형태로 다시 보내야 한다.

---

## 안 될 때

| 증상 | 원인 |
|---|---|
| `SITE_KEY가 설정되지 않았습니다` | 3단계 환경 변수 누락. 등록 후 재배포 |
| `접속 코드가 없거나 올바르지 않습니다` | 링크의 `?key=`가 틀렸거나, 코드를 바꾼 뒤 옛 링크로 접속함 → 배지 클릭해서 새 코드 입력 |
| `D1 바인딩(DB)이 설정되지 않았습니다` | `wrangler.toml`의 `database_id`가 비어 있거나 잘못됨 |
| 배지가 안 보임 | Worker가 배포되지 않았다. `src/worker.js`·`wrangler.toml`이 저장소에 있는지 확인 |

---

## 로컬에서 그대로 쓰기

`/api/state`가 없으면 앱은 **예전처럼 이 브라우저에만 저장**한다. 배지도 숨는다.
개발용 `node server.js`나 파일로 직접 열 때 그대로 동작한다.
