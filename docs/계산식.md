# 금액·수익률 계산식 정리

이 문서는 화면에 나오는 모든 금액과 수익률이 **어떤 식으로 계산되는지**를 코드
(`js/engine.js`, `js/app.js`)에서 그대로 옮긴 것이다. 값이 이상해 보일 때 이 문서만
보고 손으로 검산할 수 있게 쓰였다.

---

## 0. 한눈에 보는 원리

이 프로그램은 **펀드 기준가(NAV) 회계**를 쓴다. 핵심은 하나다.

> **입출금은 "현재 가격"으로 좌수를 사고파는 것이므로 수익률을 건드리지 않는다.**

계좌를 펀드 하나라고 보고, 돈을 넣으면 그날 가격으로 좌(share)를 사고, 빼면 판다.
가격(기준가)은 오직 **평가금액이 입력될 때만** 움직인다. 그래서 언제 얼마를 넣고
빼든 수익률이 왜곡되지 않는다.

```
평가금액 = 좌수 × 기준가 ÷ 1,000
```

기준가는 **1,000좌당 가격**이고 계좌 개설 시 **1,000.00**에서 시작한다.

---

## 1. 기호

| 기호 | 코드 이름 | 뜻 |
|---|---|---|
| `u` | `units` | 좌수 |
| `N` | `nav` | 기준가 (1,000좌당). 시작값 1,000 |
| `V` | `eval` | 평가금액 = `u × N ÷ 1000` |
| `P` | `principal` | **원금 흐름** — 입금하면 늘고 출금하면 주는 것이 전부 |
| `C` | `contractPrincipal` | **계약원금** — 보수 수취·재계약 때 평가금액으로 승계 |
| `Cg` | `contractPrincipalGross` | 유출분을 되살린 계약원금 (해지 시 원금에서 뺄 "남은 원금") |
| `cf`, `cp` | `contractFees`, `contractPayouts` | **현재 계약 시작 이후** 나간 보수·이익지급 |
| `F`, `Y` | `totalFees`, `totalPayouts` | **개설 이후 전체** 누적 보수·이익지급 |
| `D`, `W` | `totalDeposits`, `totalWithdrawals` | 누적 입금·출금 |
| `I` | `cumIndex` | 누적 성과 지수. 시작값 1,000 |

### 원금이 두 개인 이유

| | `P` (원금 흐름) | `C` (계약원금) |
|---|---|---|
| 입금 | `+금액` | `+금액` |
| 출금 | `−금액` | `−금액` |
| 성과보수 수취 | **변화 없음** | **보수 차감 후 평가금액으로 재설정** |
| 재계약 | **변화 없음** | **재예치 금액으로 재설정** |
| 이익지급 | 변화 없음 | 변화 없음 |
| 쓰는 곳 | **전체 성과**(요약 카드) | **개별 계좌 상세** |

보수를 떼면 그 계좌는 "새 계약"이 되어 개별 수익률이 0%로 초기화되지만,
전체 성과는 `P` 기준이라 영향을 받지 않는다.

## 2. 이벤트별 계산식

같은 날짜에 여러 건이 있으면 아래 순서로 처리한다.

```
입금·출금·평가·만기 (입력한 순서대로)
  → 이익지급·성과보수
  → 재계약
  → 전액출금(해지)
```

### 2-1. 입금 (deposit) — 금액 `A`

```
발행 좌수 Δu = A × 1000 ÷ N
u  ← u + Δu
P  ← P + A
C  ← C + A
Cg ← Cg + A
D  ← D + A
```

기준가 `N`은 **변하지 않는다**. → 수익률 불변.

### 2-2. 출금 (withdraw) — 금액 `A`

```
환매 좌수 Δu = A × 1000 ÷ N
  (Δu > u 이면 Δu = u 로 자르고 경고 표시)
u  ← u − Δu
P  ← P − A
C  ← C − A
Cg ← Cg − A
W  ← W + A
```

기준가 불변. 출금액이 평가금액을 넘을 수 있는데(보수 수취 후 손실 난 경우),
그때는 **좌수만 0까지 정리하고 원금은 입력한 금액대로 전액 차감**한다.

### 2-3. 평가 / 만기 (valuation, maturity) — 평가금액 `A`

```
좌수가 0이면 무시 (경고)

N_직전 = N
N      ← A × 1000 ÷ u          ← 여기서만 기준가가 움직인다
일간수익률 r = N ÷ N_직전 − 1
I      ← I × (1 + r)
```

좌수·원금은 그대로다. **만기(maturity)는 만기 원리금을 평가금액으로 넣는 것**일 뿐,
계산은 일반 평가와 완전히 같다(만기 도래 표시만 추가).

### 2-4. 이익지급 (payout) — 금액 `A`

이자·쿠폰·배당·상환수익의 인출.

```
Δu = A × 1000 ÷ N   (u를 넘지 않게 자름)
u  ← u − Δu
Y  ← Y + A
cp ← cp + A
```

기준가 불변, **원금 두 개 모두 불변**. 나간 금액은 `cp`·`Y`에 쌓아 두었다가
수익률 계산 때 분자에 되살린다(→ 4장).

### 2-5. 성과보수 수취 (fee) — 보수액 `A`

**차감 → 초기화** 2단계다.

```
[1단계] 차감 — 출금과 같은 자금 유출
V_before = u × N ÷ 1000
Δu = A × 1000 ÷ N   (u를 넘지 않게 자름)
u  ← u − Δu
F  ← F + A
cf ← cf + A
V_after  = u × N ÷ 1000

[2단계] 초기화 — 새 계약 시작
N  ← 1000            (기준가 수익률 0%)
u  ← V_after         (기준가가 1,000이므로 좌수 = 평가금액)
C  ← V_after         (보수 차감 후 평가금액이 새 계약의 원금)
Cg ← V_before        (보수를 되살린 기준 — 해지 시 쓸 값)
cf ← 0,  cp ← 0
```

`P`(원금 흐름)는 **건드리지 않는다**. 보수는 원금에서 나가는 것이 아니라
수익에서 지출되는 비용이기 때문이다.

> 당일 평가금액은 **보수 차감 전** 금액으로 입력해야 한다.

### 2-6. 재계약 (rollover)

```
잔액이 없으면 무시 (경고)
V_before = u × N ÷ 1000

[모드 A] compound — 원리금 재계약
  지급액 = 0                         (평가금액 전액을 그대로 승계)

[모드 B] payout — 원금만 재계약
  지급액 = V_before − C              (이익만 뽑음)
  지급액 > 0 이면:  u ← u − 지급액 × 1000 ÷ N,   Y ← Y + 지급액
  지급액 ≤ 0 이면(손실): 지급 없이 초기화만

V_after = u × N ÷ 1000
N  ← 1000
u  ← V_after
C  ← V_after
Cg ← V_before
cf ← 0,  cp ← 0
```

`P` 불변. 누적 성과 지수 `I`도 **끊기지 않고 이어진다**.

### 2-7. 전액출금 / 해지 (closeout)

```
잔액이 없으면 무시 (경고)

인출 현금  A_out = V = u × N ÷ 1000
W ← W + A_out

원금 차감액 = Cg          ← 실제 인출 현금이 아니라 "남은 원금"을 뺀다
손익 정리분 settleAdj = Cg − A_out
P ← P − Cg

u ← 0,  N ← 1000
C ← 0,  Cg ← 0,  cf ← 0,  cp ← 0
```

**왜 현금이 아니라 `Cg`를 빼는가:** 같은 정리를 "일반 출금"으로 기입했을 때와
전체 성과가 같아지게 맞춘 것이다. 이익까지 다 뽑은 계좌는 원금이 음수가 되고,
그 음수만큼이 실현이익으로 남는다.

## 3. 계좌 하나의 산출값

| 화면 표시 | 계산식 |
|---|---|
| 평가금액 | `V = u × N ÷ 1000` |
| 기준가 | `N` |
| 좌수 | `u` |
| 원금 (계약 기준) | `C` |
| 원금 (원금 흐름) | `P` |
| **기준가 수익률** | `N ÷ 1000 − 1` |
| **평가손익 (계약 기준)** | `V + cf + cp − C` |
| **원금대비 수익률** | `(V + cf + cp − C) ÷ C`   (C ≤ 0 이면 0) |
| 총손익 (원금 흐름 기준) | `V + F + Y − P` |
| **원금흐름대비 수익률** | `(V + F + Y − P) ÷ P`   (P = 0 이면 0) |
| 실보유 평가손익 | `V − P`   (나간 돈을 되살리지 않은 값) |
| **누적 성과 수익률** | `I ÷ 1000 − 1` |

### 세 수익률이 다른 이유

| 지표 | 초기화되나? | 나간 돈을 되살리나? |
|---|---|---|
| 기준가 수익률 | 보수·재계약 시 0% | — (기준가는 유출에 영향 없음) |
| 원금대비 수익률 | 보수·재계약 시 0% | 계약 시작 이후분(`cf`, `cp`)만 |
| 누적 성과 수익률 | **안 됨** | — (일간 기준가 수익률만 곱함) |
| 원금흐름대비 수익률 | **안 됨** | 개설 이후 전부(`F`, `Y`) |

## 4. 총수익(Total Return) 원칙 — 왜 유출액을 더하는가

펀드가 배당을 지급하면 잔액은 줄지만 원금은 안 줄어든다. 이때 수익률을
`지급 후 잔액 ÷ 원금`으로 재면 **지급한 만큼 수익률이 사라져 버린다.**

그래서 계좌 밖으로 나간 금액(배당·이자·성과보수)을 **분자에 되살린다.**
분배금 재투자 기준(Total Return)과 같은 방식이다.

```
        V + (나간 돈) − 원금
수익률 = ─────────────────────
              원금
```

* 계약 기준은 **계약 시작 이후** 나간 돈(`cf + cp`)만 되살린다
* 원금 흐름 기준은 **개설 이후** 나간 돈 전부(`F + Y`)를 되살린다
* 기준가는 유출액만큼 좌수를 상환하므로 애초에 왜곡이 없다

결과적으로 배당을 주든 보수를 떼든 **어느 화면에서도 수익률이 깎여 보이지 않는다.**

## 5. 전체 합계 (상단 요약 카드)

계좌별 값을 그대로 더한다. 해지된 계좌도 빠지지 않는다.

| 카드 | 계산식 |
|---|---|
| **총 원금** | `Σ P` |
| **총 평가금액** | `Σ V` |
| **평가손익** | `Σ (V − P)`  ← 현재 보유 기준(나간 돈 제외) |
| 총성과 | `Σ (V + F + Y − P)`  ← 나간 돈 포함 |
| **종합 성과 수익률** | `종합지수 ÷ 1000 − 1` (→ 6장) |
| **원금대비 단순 수익률** | `Σ(V + F + Y − P) ÷ Σ P` |
| 누적 성과보수 | `Σ F` |
| 누적 이익지급 | `Σ Y` |
| 누적 입금 / 출금 | `Σ D` / `Σ W` |

카드의 보조 문구도 같은 값에서 나온다.

```
"원금 대비 1.62배"   = 총 평가금액 ÷ 총 원금
"원금대비 61.73%"    = 평가손익 ÷ 총 원금
"입금 … − 출금 …"    = Σ D,  Σ W
```

> **평가손익과 원금대비 단순 수익률이 왜 다른가:** 평가손익은 지금 계좌에 남아
> 있는 돈만 본다(`Σ(V−P)`). 단순 수익률은 이미 빼 간 보수·배당까지 성과로
> 인정한다(`Σ(V+F+Y−P)`). 보수를 한 번도 안 뗐다면 둘은 같다.

## 6. 종합 성과 수익률 (컴포지트 지수)

여러 계좌를 하나의 포트폴리오로 묶어 재는 값이다. **금액 합계가 아니라
일간 수익률을 평가금액으로 가중평균해서 곱해 나간다** — 입출금 타이밍이
전체 성과를 왜곡하지 않게 하기 위해서다.

날짜 `d`에 대해:

```
S = 그날 평가가 입력된 계좌들

           Σ(i∈S)  w_i × r_i
   r_d = ───────────────────────────
         Σ(i∈S) w_i + Σ(j∉S) lastEval_j

     w_i       = 계좌 i의 직전 평가금액 (beginEval)
     r_i       = 계좌 i의 그날 일간 기준가 수익률
     lastEval_j = 평가가 없는 계좌 j의 마지막 마감 평가금액 (수익률 0으로 참여)

   지수 ← 지수 × (1 + r_d)          시작값 1,000
```

* 계좌는 **첫 평가일부터** 편입된다
* 입출금·보수·해지로 잔액이 바뀌면 **그날 마감 잔액**으로 가중치를 갱신한다
* 전액 출금된 계좌는 이후 가중치 0으로 자연히 빠진다

```
종합 성과 수익률 = 지수 ÷ 1000 − 1
```

## 7. 차트 · 벤치마크

| 항목 | 계산식 |
|---|---|
| 종합 성과 지수 곡선 | `y = 지수 ÷ 1000 − 1` (시작점 0%) |
| 계좌별 누적 수익률 곡선 | `idx ← idx × (1 + r)` 후 `y = idx ÷ 1000 − 1` (시작 1,000) |
| 벤치마크(코스피) 곡선 | `y = 지수값 ÷ 차트_첫시점_지수값 − 1` |
| 지수 바의 "설정일 대비" | `최신 지수값 ÷ 설정일 지수값 − 1` |

벤치마크는 해당 일자의 값이 없으면 **그 이전 마지막 값**을 쓴다(휴장일 대응).
계좌 설정일보다 지수 데이터가 늦게 시작하면 데이터 첫 값을 기준으로 삼고,
라벨에 "데이터 시작일 대비"로 표시한다.

## 8. 표시 규칙

* 금액은 **원 단위로 반올림**한 뒤 천 단위 구분 → `55,967,232,129원`
* 음수 부호는 하이픈이 아니라 `−`(U+2212)로 통일
* 수익률은 소수점 **둘째 자리**까지 → `23.74%`
* 기준가는 소수점 둘째 자리, 좌수는 정수
* 손익 색은 한국 관례: **이익 = 적색**, 손실 = 청색
* 모바일(≤640px)의 카드·목록은 억/만 축약 → `381억 2,984만원`
  (원금 원장·거래 이력처럼 대사가 필요한 표는 항상 전체 자릿수)

## 9. 검산용 대조표

| 화면 | 위치 | 값 |
|---|---|---|
| 상단 카드 5개 | 요약 | 5장 |
| 좌측 레일 | 계좌별 | `V`, 계약 기준 수익률, `N` |
| 계좌 목록 표 | 계좌별 | `C`, `V`, 계약 손익, `N`, 기준가 수익률, 원금대비 수익률 |
| 상세 지표 8칸 | 계좌 1개 | `N`, `u`, `C`, `V`, 수익률 4종, `F` |
| 원금 원장 | 계좌 1개 | 입출금 흐름과 `P` |
| 일별 평가·수익률 | 계좌 1개 | 일자별 `V`, 원금대비·기준가 수익률, `N` |
| 상세 거래·평가 이력 | 계좌 1개 | 이벤트별 전체 |
| 엑셀 다운로드 | 전체 | `u`, `C`, `P` 포함 **전 항목** |

> 화면 표에서는 좌수를 빼 두었다(폭 때문에). **좌수·원금 전체 값은 상세 지표와
> 엑셀 다운로드에 그대로 있으므로 검산은 그쪽에서 하면 된다.**

## 10. 자주 걸리는 함정

**1. 같은 날 입금과 평가를 함께 넣을 때**
입금을 먼저 기입하면 직전 기준가로 좌수가 발행된 뒤 평가로 기준가가 갱신된다.
평가를 먼저 기입하면 그날 갱신된 기준가로 발행된다.
→ **입금액이 그날 평가금액에 이미 포함돼 있다면 입금을 먼저 기입해야 한다.**

**2. 성과보수 수취일의 평가금액**
반드시 **보수 차감 전** 금액을 넣는다. 차감은 프로그램이 한다.

**3. 좌수가 0인 상태의 평가 입력**
무시되고 경고가 뜬다. 잔액이 없는 계좌에는 먼저 입금이 필요하다.

**4. 해지 후 원금이 음수**
정상이다. 원금보다 많이 인출했다는 뜻이고, 그 초과분이 실현이익으로 잡힌다.

**5. 개별 계좌 수익률이 0%로 리셋됐는데 전체는 그대로**
보수 수취·재계약이 있었다는 뜻이다. 개별은 계약원금 `C` 기준이라 초기화되고,
전체는 원금 흐름 `P` 기준이라 영향을 받지 않는다. **둘 다 맞는 값이다.**

## 부록. 손으로 따라가는 검산 예제

가장 헷갈리는 **보수 수취**와 **해지**가 들어간 사례다. 아래 숫자는 실제 엔진
출력과 한 원도 틀리지 않게 대조한 값이다.

**입력한 내역**

| 일자 | 구분 | 금액 |
|---|---|---|
| 2026-01-01 | 입금 | 100,000,000 |
| 2026-01-31 | 평가 | 130,000,000 |
| 2026-01-31 | 성과보수 | 6,000,000 |
| 2026-02-28 | 평가 | 136,400,000 |
| 2026-02-28 | 전액출금(해지) | — |

**단계별 계산**

```
① 입금 1억
   좌수 u = 100,000,000 × 1000 ÷ 1000 = 100,000,000
   N=1,000   P=100,000,000   C=100,000,000   Cg=100,000,000

② 평가 1.3억
   N = 130,000,000 × 1000 ÷ 100,000,000 = 1,300.00
   일간수익률 r = 1300÷1000 − 1 = +30.00%
   I = 1000 × 1.30 = 1,300

③ 성과보수 600만  ← 2단계로 처리
   [차감] V_before = 130,000,000
          Δu = 6,000,000 × 1000 ÷ 1300 = 4,615,384.6
          u  = 100,000,000 − 4,615,384.6 = 95,384,615.4
          V_after = 95,384,615.4 × 1300 ÷ 1000 = 124,000,000
   [초기화] N  = 1,000
            u  = 124,000,000        (기준가 1,000이므로 좌수 = 평가금액)
            C  = 124,000,000        ← 계약원금이 여기서 재설정
            Cg = 130,000,000        ← 보수를 되살린 기준
            F  = 6,000,000
            P  = 100,000,000        ← 그대로! 보수는 원금에서 안 나간다

④ 평가 1.364억
   N = 136,400,000 × 1000 ÷ 124,000,000 = 1,100.00
   r = 1100÷1000 − 1 = +10.00%
   I = 1,300 × 1.10 = 1,430

⑤ 해지
   인출 현금 = 136,400,000
   원금 차감 = Cg = 130,000,000     ← 현금이 아니라 "남은 원금"
   P = 100,000,000 − 130,000,000 = −30,000,000    ← 음수가 정상
   손익 정리분 = 130,000,000 − 136,400,000 = −6,400,000  (이익 정리)
```

**최종 결과**

```
총손익  = V + F + Y − P
        = 0 + 6,000,000 + 0 − (−30,000,000)
        = 36,000,000원

누적 성과 수익률 = I ÷ 1000 − 1 = 1,430 ÷ 1000 − 1 = 43.00%
                 ( = 1.30 × 1.10 − 1 )
```

**읽는 법:** 1억을 넣어 보수 600만원을 떼고 최종 1억 3,640만원을 찾았으니
실제로 번 돈은 `136,400,000 + 6,000,000 − 100,000,000 = 42,400,000원`이다.
위 총손익 36,000,000원과 다른 이유는, 총손익이 **원금 흐름 기준**(`P`가 −3천만)
으로 계산되기 때문이다. 두 값 모두 각자의 기준에서 맞으며, 여러 계좌를 합쳐
전체 실적을 볼 때는 원금 흐름 기준이 일관된다.

한편 **운용 성과 자체**는 43.00%다 — 1월 +30%, 2월 +10%를 곱한 값이고,
보수를 떼든 말든 이 숫자는 변하지 않는다.
